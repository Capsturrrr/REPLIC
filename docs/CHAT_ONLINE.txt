RUDP CHAT OVER THE INTERNET (two people, two machines)

Build once:   git pull && make chat

OPTION A (most reliable): Tailscale
 1. Both install Tailscale (tailscale.com/download), log in, join the same tailnet
    (one person shares their machine with the other).
 2. Each runs  tailscale ip -4  and tells the other their 100.x.x.x address.
 3. Run at the same time:
      you:    ./bin/chat 9001 FRIEND_100.x.x.x:9001 Harsh 20
      friend: ./bin/chat 9001 YOUR_100.x.x.x:9001 Rohit 20
    (the 20 is simulated extra packet loss; use 0 for none)

OPTION B: public IPs (works only on home routers, usually not hostel Wi-Fi)
 1. Each finds their public IP (search "what is my ip").
 2. Run within a few seconds of each other:
      you:    ./bin/chat 9001 FRIEND_PUBLIC_IP:9001 Harsh
      friend: ./bin/chat 9001 YOUR_PUBLIC_IP:9001 Rohit
    It prints "Connected to ..." when the path opens.

Same machine, two terminals still works:
   ./bin/chat 9001 9002 Alice 30     ./bin/chat 9002 9001 Bob 30

WEB VERSION (browser UI, same protocol, talks to ./bin/chat or another web copy)
   python3 web/rudp_web.py --udp 9001 --peer FRIEND_IP:9001 --name Harsh --http 8080
   open http://localhost:8080
   Right panel: live packet-loss slider, sent/lost/resent counters, in-flight window, protocol log.

WINDOW CONTROLLER (browser version only)
   Dropdown: Fixed window (8) / AIMD / Poise (Q-learning, loads results/q_lossy.txt, keeps learning).
   "Send 60 test messages" times delivery. For a slow lossy path add:  --loss 10 --delay 40
   (Poise did not beat the simple controllers in our tests, same as the report.)

RETRAIN / EVALUATE THE CHAT AGENT
   python3 web/train.py   (about 5 s; writes results/q_chat.txt and prints the held-out comparison table)

Deep (neural network) controller
   python3 web/train_deep.py        trains 4 seeds, keeps the best on validation paths, writes results/dqn_chat.json
   Pick "Poise (deep, neural net)" in the controller dropdown. Needs numpy only (no torch).
   Training is seed-sensitive (1 of 4 seeds was worse than AIMD), hence the validation pick.
   Stress test with all controllers: python3 web/stress.py

Neural agent in the C transport
   make smart sack ; python3 web/export_dqn.py
   ./bin/smart_client --mode deep --init 10 --dfile results/dqn_chat.txt ...   (see README)

Live dashboard and adaptive timeout (web chat)
   The right-hand panel plots window, packets in flight, RTT and loss for the last 60 seconds.
   The gateway now uses an RFC 6298 retransmission timer with backoff by default (--rto adaptive);
   --rto fixed restores the old fixed 300 ms timeout.

Selective Repeat is the default in the web chat and in ./bin/chat. Add --gbn (gateway) or set RUDP_GBN=1 (./bin/chat)
to get the old Go-Back-N behaviour. Both ends should use the same mode.

Window and agent settings (gateway): the receive window and ACK bitmap are 256 packets / 32 bytes, the same as the C transport and ./bin/chat, so
the gateway and the terminal chat interoperate (tests/chat_interop.sh). --cap 128 (default) is the window ceiling, --ssdeep 64 (default) is the
classic slow-start phase before the neural agent takes over, --hybrid 0.10 (default) hands control to AIMD under heavy loss. Use --cap 32 --ssdeep 0
--hybrid 0 for the original behaviour. The checksum is CRC-16, so old binaries cannot talk to new ones.
